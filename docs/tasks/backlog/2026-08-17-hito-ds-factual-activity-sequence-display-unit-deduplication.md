## Scope

Correct the shared `HitoFactualActivityPointSequence` presentation of Backend-formatted observation
values and align the existing `/hitoDS` point-sequence playground to that same input contract. The
correction applies to every current and future DS consumer of that primitive; Product will then

## Archive Intent

Retain through the focused Frontend replay, then compact to the single formatting contract and its

## Task

Render every supplied observation `displayValue` exactly once. `displayValue` is already the
Backend's human-readable factual value, including any unit or pace notation. Retain `unitLabel` as
separate semantic metadata where the component itself produces a bare numeric axis value, but never
append it to an existing `displayValue`. Rewrite the existing playground's static observation
`displayValue` literals to this same complete-string contract.

## Canonical Formatting Invariant

For every current or future factual-sequence metric:

- `value` is the numeric observation used for geometry and scale calculation;
- non-null `displayValue` is the complete, render-ready factual text and is shown verbatim;
- `unitLabel` is semantic metadata and may be paired only with a number generated by the component
  itself, never parsed from or appended to `displayValue`.

The primitive must not maintain a metric list, detect suffixes, branch for legacy bare values, or
guess whether a value already contains a unit. Any canonical DS reference fixture supplies the same
complete `displayValue` shape as the Backend contract.

## User Report

Independent QA of authenticated Runner Progress observed duplicated units in the factual activity
sequence: for example `16.2 km km`, `100 min min`, `6:10/km /km`, `96 m m`, and `500 AU AU`.

## Evidence

The completed Frontend adoption receipt records the browser and independent QA reproduction. Source
inspection confirms both defective shared render paths:

- `src/components/ui/hito-factual-activity-point-sequence.tsx` renders
  `{maxObservation.displayValue} {metric.unitLabel}` for the scale label;
- the shared `observationValue` helper returns
  `` `${observation.displayValue} ${observation.unitLabel}` `` for point readback, accessible
  names, and the native table.

## Observed Behavior

The primitive duplicates units in visible plot/readback/table values and in accessibility names,
despite receiving already formatted Backend `displayValue` strings.

## Expected Behavior

Each observation has one factual value such as `16.2 km`, `100 min`, `6:10/km`, `96 m`, or
`500 AU`. Generated zero-axis labels may still combine a bare numeric `0` with the selected metric's
unit. No Product route transforms Backend values.

## Source Investigation

Backend formatting in `src/lib/runner-activity/metric-formulas.ts` is the canonical human-readable
value authority; `unitLabel` remains separately supplied metadata. The Frontend Product consumer
passes the Backend sequence unchanged, as its task requires. The first incorrect canonical owner is
therefore the shared Design System primitive, not the API or Progress route.

## Confirmed Root Cause

`HitoFactualActivityPointSequence` treats its already formatted `displayValue` as a bare number and
appends a second unit in two shared paths.
