## Original Problem

The former deterministic 10-week 10K builder selected only strides and tempo for development
touches. Supported runners could therefore receive no intervals or hills, making the output look
generic despite passing structural validation.

The historical response specified a week-by-week 10K matrix by runner level and load context. It
required controlled intervals for supported standard-load runners, added hills for stronger
profiles, protected beginners from forced intensity, and kept cutback and endpoint weeks explicit.

## Durable 10K Lessons

- A 10K plan should express rhythm, repeatability, turnover, aerobic support, recovery, and an exact
  selected-distance endpoint.
- Beginner plans must not add intervals or hills solely to appear varied.
- Supported plans should normally contain meaningful 10K development beyond repeated easy running,
  but the appropriate session mix depends on the complete runner context.
- Strides, tempo, intervals, hills, progression, and other 10K-relevant work must have a clear
  purpose and recoverable placement.
- The next running contact after demanding intervals, hills, or a long run should protect recovery.
- Cutback weeks must reduce stress, and final preparation must retain rhythm without late
  compensatory loading.
- Exact `10000m` endpoint truth remains required when the selected goal is 10K.

These are review principles, not mandatory fixed counts for every current plan.

## Superseded Decisions

The former fixed 10-week schedule, runner-level matrices, week-number selector, mandatory interval
and hill counts, deterministic backend handoff, and prohibition on AI normal-path authorship are no
longer current.

The old metric wording is also superseded: a benchmark can improve pace precision but is not
required for accepted AI-authored estimated pace, and executable BPM may use an immutable accepted
estimated or personal profile snapshot under the current target contract.

## Authority Boundary

This file is subordinate to current product/system truth, the implemented provider/compiler and
review/confirm contracts, accepted watch-target policy, and the Running Coach doctrine digest.
It must not be used as a live 10K authoring matrix, validator specification, or backend workout
selector. Full historical tables remain available through Git history at this stable path.
