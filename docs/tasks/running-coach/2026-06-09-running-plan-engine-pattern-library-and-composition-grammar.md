## Original Problem

The former deterministic builders selected isolated workouts but lacked a shared composition
language. Quality fixes therefore accumulated family by family, and plans could be safe yet
repetitive, poorly phased, or dependent on one long run for all visible meaning.

This record introduced adaptation, base, build, specific, cutback, taper, endpoint, and recovery
week concepts plus a workout-pattern library. It also linked those patterns to the retired 10K,
Half Marathon, and Marathon Base matrices.

## Durable Composition Lessons

- A complete plan needs coherent adaptation, development, absorption, specificity, taper, and
  endpoint intent rather than a random sequence of workouts.
- Easy and recovery running form the support backbone; steady, progression, tempo, threshold,
  intervals, hills, strides, and long-run variants should appear only when they have a clear
  coaching purpose.
- Quality sessions need executable warm-up, work, recovery where appropriate, and cooldown anatomy.
- Repeat structure must express real repeatability; complexity must not be added for appearance.
- Development stress needs credible spacing from other demanding sessions and the long run.
- A cutback must reduce total stress, not merely change the label.
- Long-run growth and role should evolve without unsafe early duration, arbitrary splitting, or
  unsupported race-readiness claims.
- Plans should differentiate runner support and availability without turning conservative cases
  into generic filler.
- Endpoint sessions must express the selected distance honestly.

These concepts remain useful when reviewing an AI-authored program. The old archetype keys, fixed
counts, family tables, and week sequences are not a current authoring or validation contract.

## Superseded Decisions

Do not use this file to:

- make Backend choose workouts, phases, density, long-run roles, or taper content;
- restore a deterministic composition layer or fixed one-development-touch matrix;
- treat `Marathon Base` as a current selected-goal family or fallback;
- require old interval, hill, threshold, or pattern counts by runner label;
- reject accepted AI-authored pace because no benchmark exists;
- require personal rather than accepted estimated profile truth for executable BPM;
- replace current child-first sections, target semantics, or review/confirm exactness.

AI currently authors the complete calendar and its coaching content. Backend parses, validates,
compiles, reviews, confirms, persists, and reads back that exact accepted truth without semantic
fallback or coaching substitution.

It must not serve as a live pattern registry, backend handoff, validator checklist, or product-family
definition. Full historical tables remain available through Git history at this stable path.
