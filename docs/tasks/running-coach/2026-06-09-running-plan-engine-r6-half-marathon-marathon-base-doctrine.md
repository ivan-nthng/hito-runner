# Half Marathon And Marathon Base R6 Doctrine - Historical Record

Date: 2026-06-09
Owner: Running Coach
Status: historical; deterministic family expansion superseded by selected-distance AI authoring

## Original Problem

The deterministic preview engine had a credible 10K vertical but no sufficiently distinct Half
Marathon or full-marathon product. This document opened an exact 21.1K family and deliberately
limited the second family to Marathon Base so the product would not overclaim marathon readiness.

## Decision At The Time

- Half Marathon received exact `21100m` endpoint rules, durability-led development, long-run
  progression, cutbacks, and conservative quality-session limits.
- Marathon Base received aerobic durability, time-on-feet, recovery, and long-run roles without an
  exact `42195m` endpoint or completion/race-readiness promise.
- The backend was expected to choose family-specific workouts from deterministic matrices.

The deterministic family ownership, fixed horizon recommendations, and Marathon Base product family
are no longer current.

## Durable Lessons

- A Half Marathon plan must show sustained durability, long-run development, and late
  distance-specific meaning; generic tempo repetition is insufficient.
- Marathon-oriented training must distinguish aerobic base work from an actual marathon completion
  or performance promise.
- Family identity must survive runner-facing titles, segments, review, persistence, and readback.
- Long-run growth needs cutbacks and protected recovery; harder midweek work must not be compressed
  against the long run.
- Exact selected-distance goals require exact endpoint truth.
- No plan should make medical claims or invent personal physiological certainty.

## Supersession Boundary

Current Quick setup sends a selected distance and runner facts to the AI-authored plan-first path.
Backend validates and compiles that plan; it does not select a Half Marathon or Marathon Base recipe.

Do not use this file to:

- treat Marathon Base as current product truth or a fallback for a Marathon goal;
- copy the old runner-level workout matrix into backend policy;
- reject AI-authored estimated pace or accepted-profile BPM under the old metric rules;
- restore preview-only, no-AI, or deterministic authoring instructions.
