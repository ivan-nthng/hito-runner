# Selected-Plan Stimulus Contract - Historical Record

Date: 2026-06-09
Owner: Running Coach
Status: historical; deterministic stimulus matrix superseded by AI-authored plan-first truth

## Original Problem

Technically valid deterministic previews could still feel like safe calendars rather than real
programs. Supported Half Marathon plans were especially prone to generic tempo repetition, while
Marathon Base depended too heavily on long-run labels for visible identity.

## Decision At The Time

The document created runner-level tables for strides, tempo, threshold, intervals, hills, and
long-run-specific work. It capped the deterministic v1 engine at one development touch per week and
defined family-specific minimum mixes for 10K, Half Marathon, and Marathon Base.

Those fixed identity counts, level matrices, and backend selection rules are no longer live policy.

## Durable Lessons

- Technical validity does not prove coaching quality.
- Variety must serve adaptation and goal specificity; random novelty and extra hard days are not
  acceptable substitutes.
- Easy and recovery running must remain the majority of normal recreational training.
- Development sessions and demanding long runs require recovery spacing.
- A long run with a deliberate stronger finish can be the week's main development stimulus.
- Cutback and taper weeks reduce load without erasing the goal's identity.
- 10K training should show controlled rhythm and repeatability; Half Marathon training should show
  sustained durability; marathon-oriented base work must remain distinct from race preparation.
- Runner-facing richness must survive review, persistence, calendar/detail readback, and export.

## Supersession Boundary

AI now owns workout mix, density, progression, and session placement. Backend validates the authored
plan against structural, calendar, target, review, and persistence contracts; it must not recreate
the old stimulus matrix as a fallback planner.

Do not use this file to:

- require exact counts of historical identities;
- enforce a universal one-development-touch rule irrespective of runner context;
- restore Marathon Base as a current selected-plan family;
- reject truthful AI-authored numeric pace or accepted-profile BPM commands.
